# Direction, Not Magnitude

Code and experiment results for **"Direction, Not Magnitude: Why Different Compression Mechanisms Harm Different Groups"** (CPAL 2027 submission). The compiled paper is at [`main.pdf`](main.pdf); source is [`main.tex`](main.tex).

**Core claim.** Existing disparate-impact theory for model compression bounds a group's excess loss using only the *magnitude* of the weight perturbation, which makes it blind to which compression *mechanism* produced that perturbation. We show the exact (un-bounded) second-order term is not mechanism-blind, and that direction-aware predictors (full Hessian, diagonal, or even a bare first-order gradient term) correctly identify which group a mechanism harms most far more often than magnitude-only predictors do.

Model checkpoints (`*.pt`) and downloaded datasets (`code/data/`, `code/data_waterbirds/`) are **not** included in the repo (see `.gitignore`) — they're regenerated by the scripts below.

## Setup

Requires Python 3.11+ (functorch/`torch.func`-based HVPs; developed against PyTorch 2.x).

```bash
pip install torch torchvision scipy numpy pandas pillow
```

Everything was run on Apple Silicon (MPS backend); the scripts fall back to CPU automatically if MPS isn't available (`torch.device("mps" if torch.backends.mps.is_available() else "cpu")`).

### Data

**CIFAR-10 substitute benchmark** (the paper's main benchmark, Section 5): downloads automatically on first run via `torchvision.datasets.CIFAR10(download=True)` into `code/data/`.

**Waterbirds** (the real-dataset replication, Appendix): the original CodaLab-hosted download is dead (documented in the paper). We used an independently-hosted HuggingFace mirror of the identical official split, `grodino/waterbirds`. Download `train.parquet` and `test.parquet` from that dataset repo into `code/data_waterbirds/`, e.g.:

```bash
pip install huggingface_hub
huggingface-cli download grodino/waterbirds --repo-type dataset \
  --include "train.parquet" "test.parquet" --local-dir code/data_waterbirds
```

## Reproducing the results

All commands below are run from `code/`. Each `run_gate*.py` trains (or loads a cached checkpoint, if present) and writes a `gate_results*.json`; each `baseline_compare*.py` reads the corresponding `gate_results*.json` plus the checkpoint to compute the full 5-predictor comparison.

### Main comparison (Table 1, Figure 1, Section 6)

```bash
python run_gate.py            # trains ResNet-18 x 3 seeds (~5-10 min total on Apple Silicon),
                               # calibrates all 4 mechanisms to ||delta||/||theta*||~3%,
                               # writes gate_results.json
python baseline_compare.py    # full/diagonal/first-order/isotropic/norm-bound comparison
                               # writes baseline_compare_results.json
```

If `code/ckpt_seed{0,1,2}_minfrac15.pt` already exist, `run_gate.py` loads them instead of retraining.

### Severity sweep (Appendix: validity frontier)

Holds the main checkpoints fixed and recalibrates all four mechanisms at four severity targets (1%, 3%, 10%, 25%):

```bash
python severity_sweep.py      # writes severity_sweep_results.json, severity_sweep_summary.json
```

This is memory-hungry on MPS; the script checkpoints per-seed to `severity_sweep_results.json` and resumes automatically from there if re-run after a crash (we hit repeated MPS allocator OOMs processing more than one seed's sweep in a single long-lived process — if you hit the same issue, re-running the script picks up from the last completed seed).

### Disjoint predictor/evaluation split

Checks that the predictors (fit on a 50-example batch per group) aren't sharing sampling noise with the actual-loss measurement:

```bash
python test_peeking_check.py  # writes test_peeking_check_results.json
```

### Weight-decay ablation

Retrains with standard SGD weight decay (5e-4) to test whether the findings depend on the unregularized-training premise of Proposition 1:

```bash
python run_gate_weight_decay.py          # retrains 3 seeds (~20 min total), writes gate_results_weight_decay.json
python baseline_compare_weight_decay.py  # writes baseline_compare_weight_decay_results.json
```

### Waterbirds replication (Appendix)

Requires `code/data_waterbirds/{train,test}.parquet` (see Data above). Each CIFAR-substitute script above has a Waterbirds counterpart with the same role, run in the same order:

```bash
python run_gate_waterbirds.py                 # 8-epoch (overfit) regime -> gate fails
python run_gate_waterbirds_earlystop.py       # 3-epoch (early-stopped) regime -> gate passes
python baseline_compare_waterbirds.py
python baseline_compare_waterbirds_earlystop.py
python severity_sweep_waterbirds.py
python test_peeking_check_waterbirds.py
python run_gate_waterbirds_weight_decay.py
```

### Additional post-hoc analyses

These read already-produced `*.json` results (no retraining) and address specific reviewer questions; they are not yet referenced in the current paper text:

- `significance_tests.py` — exact binomial tests, paired McNemar's tests, and a seed-cluster bootstrap CI on the 12 flip-case accuracies in `baseline_compare_results.json`.
- `analyze_per_layer.py` / `analyze_layer_structure.py` — per-layer contribution breakdown of `g_a^T delta`, checking whether BatchNorm scale-invariance or a specific layer's scaling drives the group-ranking flips (needs the main checkpoints).
- `analyze_locality_gap.py` — quantifies the Taylor expansion's residual (`actual_dloss - predicted_dloss`, the dropped `O(||delta||^3)` term) directly from `gate_results_waterbirds*.json`, to locate where the second-order approximation breaks down.
